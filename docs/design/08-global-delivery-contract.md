# 全Skill通用完整精读契约

当前要求（2026-11-08）：至少90页有效教学正文、全书至多10个可见主章，首次按完整百页级课程充分写作，
不先做短整书再凑页；几何图解可达几十幅以上，按所有有用机会落地。变量、条件与逐步推导在公式使用处交代。
构建器在首稿仍planned/composing时阻止编译，随后核真实标题与物理页数；教学质量仍另验。
缓存新增短片段定位以减少全文回传，旧70/71页契约也继承90页门槛。
最新实际验证见[90页与首次成稿验证](../../evals/results/first-manuscript-90-validation.md)。下文为历次修订记录。

2026-11-07。用户明确要求修订整个Skill，删除旧阅读记录后仍可从原文独立执行，
并新增完整稿超过70页的硬下限。这不是针对某一篇文章的改写任务。

本次以[通用契约](../../skills/math-research-reader/references/delivery-contract.md)作为完整精读的统一规则：
相关本科基础、研一专题初学者；至少71页有效教学正文；完整背景桥梁、通式、证明与几何图解；
正常A4/11pt数学排版；不足持续补写，真实受阻只留阶段稿，不改称短版完整稿。
短论文不再自动豁免，局部/专项/导出仍保持自己的范围，不能作为完整任务的替代。

入口、默认提示、八阶段阅读、长篇成稿、写作计划、知识库、质量与导出规则同步接入。
删除长篇规范中的固定密码学专题补课案例，改为依据每篇论文实际依赖规划；
随包自编样例保留为讲解示范，不能拿来替代任何新论文的读取。

已有唯一构建器新增`--full-read`及book的`task_mode=deep-read`触发门槛，
用实际Poppler `pdfinfo`检查编译结果至少71个物理页后才原子替换输出。
这不自动判断有效正文、真实性或教学质量，仍需逐页内容验收。
没有新增运行脚本、没有重写用户论文、没有发布GitHub更新。
实现、边界和实际测试见[验证记录](../../evals/results/full-read-contract-validation.md)。

后续反馈进一步收紧执行方式：以[导师式课程展开](../../skills/math-research-reader/references/deep-read.md)
逐知识点推进，不将checkpoint视为主动交付点；默认不生成阶段PDF/压缩包。
压缩入口规则并按需加载细则，复用同版本来源与未变检查，完整精读契约还从工作区state/plan继承，
